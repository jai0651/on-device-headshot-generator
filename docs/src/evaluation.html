Why this exists before any training

Every later decision is a measurement: which LoRA checkpoint, whether FaceID beats the LoRA, whether 4-bit quantization broke the face. Without these instruments, each of those would be a guess made by squinting at pictures. And one number alone can be fooled: a LoRA that memorised the selfies scores brilliantly on identity and ignores every prompt. So there are three instruments, measuring things that trade against each other.

Instrument 1: identity

A face-recognition network maps a face to a 512-number vector, trained so that two photos of the same person land close together and photos of different people land far apart. "Close" is measured by cosine similarity: 1 means identical direction, 0 means unrelated.

Two recognizers, on purpose

Primary: buffalo_l (ArcFace R50, trained on WebFace600K). Secondary: antelopev2 (ArcFace R100, trained on Glint360K). Different backbone and different training data.

The circularity rule

IP-Adapter-FaceID is conditioned on buffalo_l's embedding. Scoring FaceID with buffalo_l would be grading it with the model it was built to please. So for FaceID, only the secondary score counts, and stage 5 reports the secondary for every method.

Proving it works: 1000 real photo pairs

Before trusting it, the instrument was run on LFW's standard test split: 500 pairs of the same person, 500 pairs of different people, all real photos.

Green: same person (mean 0.64). Red: different people (mean 0.01). The two recognizers agree on 98.7% of decisions.

The threshold: 0.30

The histograms leave a clear gap between about 0.2 and 0.35. The mathematically "equal error" point is 0.15, which sits on the edge of the stranger distribution, so the project uses cos ≥ 0.30 as "this is the same person". It's also what the on-device identity guard will use to reject a bad generation.

Instrument 2: prompt adherence (CLIP)

CLIP was trained to put an image and its caption close together. So 100 × cos(image, prompt) goes up when the picture shows what was asked for. It's crude: typical scores sit in the 20s, and a few points is a real difference. But it moves the right way when a model stops listening, which is exactly the failure identity can't see.

Proving it works: break images on purpose

A mutation test takes a base image and injects one known defect at a time: tilt it 12°, blur it, shift it off-centre, paint a busy background, darken one side of the face, zoom until the crown leaves the frame. The matching check has to flip from pass to fail. It caught 8 of 9 testable defects. The untested ones (background, shadow, sharpness) were already failing on every base image, because plain SD 1.5 never produced a truly compliant photo to break.

Each base image, then one mutation per tile, with the checks that still pass.

The fixed prompt set

8 prompts × 3 frozen seeds = 24 images per method. Every checkpoint, method and (later) quantization level generates exactly these, which is what makes the numbers comparable. {subject} is "ohwx man" with the LoRA, "a man" otherwise. The set is versioned: v2 fixed two prompts whose images hid the face, and scores are only compared within one version.

The floor: plain SD 1.5

Every method has to beat this. With no identity conditioning, every image is a stranger (identity ≈ 0), and not one of 24 images passes every compliance check.
